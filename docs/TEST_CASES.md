# Test cases for completed milestones

Scope: completed M0–M3b behavior only. These cases are for the synthetic-data prototype; do not use real financial information. M4 upload/review and later forecast, insights, chat, and readiness flows are outside this test set because they are not implemented yet.

## Run and reset

Run `npm ci`, then `npm run dev` from the repository root. Open the Vite URL and use `localStorage.clear()` in the browser console followed by a reload when a clean state is needed. Automated checks are `npm test`, `npm run typecheck`, `npm run lint`, `npm run format:check`, `npm run build`, and `npm run test:e2e`.

## Automated coverage already in the repository

- `src/app/App.test.tsx`: shell disclosure, navigation and recovery notice.
- `src/domain/types.test.ts`: occurrence linkage, status consistency and transaction/OCR schema constraints.
- `src/domain/availableBalance.test.ts`: opening-reference inclusion and business-timezone behavior.
- `src/domain/scheduleLifecycle.test.ts`: one-time catch-up/idempotency, unpaid preservation, month-end clamping, start/end boundaries, monthly catch-up and forecast generation.
- `src/store/demoStore.test.ts`: one-time and monthly store actions, persistence recovery, linked correction, delete and undo.
- `e2e/navigation.spec.ts`: responsive navigation at 360/768/1280 px, opening balance/manual transaction flow, one-time lifecycle, and monthly January-to-March catch-up.

## Current gaps

The responsive browser suite does not yet exercise a real screen reader or all keyboard interactions. There is no automated end-to-end test for malformed storage recovery, canceling a monthly rule, or transaction correction across a reload; the domain/store tests cover parts of those behaviors. M4 and later requirements are intentionally not represented as passing cases here.
